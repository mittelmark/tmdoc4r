## Part 2 — `vignette()` not found after install (2026-11-04)

User report: in the installed 0.6.0 package `vignette("tmdoc4r-vignette")`
fails; the user suspected a missing DESCRIPTION vignette entry and a
chicken-and-egg `VignetteBuilder` problem.

Diagnosis (all reproduced locally):

1. Installing the released tarball yields no `doc/` and no
   `Meta/vignette.rds` → "Vignette 'tmdoc4r-vignette' nicht gefunden".
   The attached tarball had been produced by
   `R CMD build --no-build-vignettes` from a tree where the Makefile moves
   every vignette product *out* of `inst/doc/`.
2. **No `VignetteBuilder` entry is needed — and none is possible** (R
   would need the package installed to build its own vignettes). The
   package uses the standard *pre-built vignette* pattern:
   `vignettes/tmdoc4r-vignette.Rnw` (passive Sweave stub with
   `\VignetteIndexEntry` + `\includepdf`) plus the products in `inst/doc/`.
3. `R CMD INSTALL` derives `Meta/vignette.rds` from `inst/doc` **alone**;
   `build/vignette.rds` (written only by a full `R CMD build`) is not
   required — proven by installing a seeded `--no-build-vignettes`
   tarball.
4. The vignette object's `Dir` field is the package **root** by design;
   `vignette()` / `print.vignette` always join `Dir/"doc"/PDF`. (An
   intermediate suspicion that CI's tarball had broken paths was a wrong
   join on the agent's side.)
5. CI's full-build tarball (run `41706381332`) has the canonical layout
   and installs correctly.

Fixes:

- **v0.6.0 release asset replaced** with CI's tarball (518,815 B) via
  `gh release upload v0.6.0 … --clobber`; closed-loop verified
  (download from the release → fresh install → `vignette()` lists it and
  `doc/PDF` exists); an *Asset note* was appended to the release body.
- **Makefile** (commit `e5c3a62`) — three changes to the `build` target:
  1. delete the current tarball up front, so the swallowed `R CMD build`
     failure can no longer make `--check` silently re-validate a stale
     archive;
  2. seed `inst/doc` with the vignette Rnw+PDF **after** the build
     attempt, so the documented TeX-less
     `R CMD build --no-build-vignettes` fallback produces a tarball where
     `vignette()` works (607,099 B — the PDF ships once, not twice);
  3. drop `vignettes/*.pdf` afterwards (only the Sweave `\includepdf`
     consumes it, and only during the build attempt).
  The placement *after* `--build` is deliberate: CI's full build writes
  its tarball first, so CI's path stays unchanged — verified in the CI
  log (`* creating vignettes … OK` → `* building …` → `cp … inst/doc/` →
  `rm -f …`), run `41788827800` green.
- Local end-to-end: `make build` (fails at TeX as known) → fallback build →
  fresh install → `vignette()` works → `R CMD check` Status OK.
- **Docs**: AGENTS.md now documents the pre-built-vignette pattern, the
  corrected fallback sequence, the CI-tarball preference for releases and
  the two related pitfalls; `.github/copilot-instructions.md` was aligned
  with the new behaviour.

## Decisions worth remembering

- Never attach a tarball to a release without a fresh install +
  `vignette()` check; prefer the **CI artifact** (full build, includes
  `build/vignette.rds`). The recovery procedure is documented in AGENTS.md
  under *Replacing a release asset with the CI build*.
- The Makefile seed must stay *after* the `--build` line — that is what
  keeps CI's full-build path untouched.
- `VignetteBuilder: tmdoc4r` is neither needed nor possible; the
  pre-built vignette pattern (Rnw stub + `inst/doc`) is the answer.
- The stylesheet is `book.css` (singular); the tutorial-book showcase
  stays untracked and is only a release asset.
